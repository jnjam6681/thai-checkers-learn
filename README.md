# หมากฮอส — AI ปะทะ AI

ให้เอนจิน **Future** ของ [hosbase.com](https://hosbase.com) เล่นหมากฮอสไทยกันเอง
ทั้งสองฝั่ง ฝั่งเรากดทีละตาเพื่อดูการเดิน พร้อมคำอธิบายว่าตานั้นน่าเดินเพราะอะไร

ต่อยอดจาก `~/Documents/playgrounds/python/bot-hosbase` ซึ่งถอดโปรโตคอลของ
hosbase ไว้แล้ว โค้ดกระดานและตัวคุยกับเอนจินในนี้พอร์ตมาจากโปรเจกต์นั้นตรงๆ

```bash
npm install
npm run dev      # เปิด http://localhost:5173
```

## เอนจินตัวเดียวเล่นสองฝั่งได้ยังไง

หนึ่งการเชื่อมต่อกับ hosbase = หนึ่งเกม และเอนจินถือได้สีเดียว เราจึงเปิดสองเกม
แล้วส่งตาข้ามไปมา

```
   เกม A                                     เกม B
   client = ขาว  ──► เอนจินถือ "ดำ"           client = ดำ  ──► เอนจินถือ "ขาว"
        ▲                    │                     ▲                 │
        │   ตาของขาว         │ ตาของดำ             │  ตาของดำ         │ ตาของขาว
        └────────────────────┴─────────────────────┴─────────────────┘
                         กระดานกลางของเรา (src/game/board.ts)
```

หมากฮอสไทยฝ่ายดำเดินก่อน เกม B จึงเป็นคนให้ตาแรกมาตั้งแต่ตอนเปิดเกม
(ส่ง `"W"` แล้วเอนจินตอบตาของดำกลับมาเลย) ส่วนเกม A ส่ง `"B"` แล้วรอ

หนึ่งแมตช์ = เปิดเกมกับ hosbase 2 เกม

## หน้าจอ

* ธีมสว่าง/มืดตามเครื่อง (`prefers-color-scheme`) สีทั้งหมดเป็น custom property
  อยู่หัวไฟล์ `src/styles.css` แก้ที่เดียวเปลี่ยนทั้งแอป
* แถวบน = ตั้งค่าเกม (เริ่มใหม่ / ใครเดินก่อน) แถวใต้กระดาน = ควบคุมการดู
  (⏮ ◀ ▶ ⏭ / เล่นเอง / ความเร็ว / โชว์ชื่อช่อง) แยกกันเพราะคนละหน้าที่
* คีย์ลัด: <kbd>←</kbd> <kbd>→</kbd> ถอยหลัง/เดินหน้า, <kbd>space</kbd> เดินหน้า,
  <kbd>Home</kbd> <kbd>End</kbd> ไปต้นเกม/ตาล่าสุด
* ตาที่ย้อนดูแล้วกดเดินหน้าจะเล่นซ้ำจาก log ไม่ยิงเน็ตใหม่ คลิกที่ตาในตารางก็
  กระโดดไปดูได้
* ไฮไลต์บนกระดาน: ทอง = ช่องที่ตัวหมากผ่าน (ปลายทางมีขอบหนา), แดง = ช่องที่โดนกิน

**ห้ามให้อะไรบนหน้าขยับตอนเดิน** เป็นข้อบังคับของหน้านี้ ทุกกล่องที่เนื้อหา
เปลี่ยนความสูงได้ (แถบสถานะ, กล่องคำวิเคราะห์, ตารางตาเดิน) ถูกล็อกความสูงไว้
แล้วให้เลื่อนข้างในแทน บวก `scrollbar-gutter: stable` กันความกว้างหน้าหด
ตอน scrollbar โผล่ และการเลื่อน log ต้องขยับ `scrollTop` ของกล่องเอง
ห้ามใช้ `scrollIntoView` เพราะมันลากทั้งหน้าตามไปด้วย

## เลือกว่าใครเดินก่อน

โปรโตคอลของ hosbase ล็อกไว้ว่า **ฝ่ายดำเดินก่อนเสมอ** (`"W"` = เราถือขาว
เอนจินถือดำแล้วเดินนำทันที, `"B"` = เอนจินตอบ `NB` แล้วรอเรา) เปลี่ยนตรงนั้นไม่ได้

แต่ตำแหน่งตั้งต้นของหมากฮอสสมมาตรกันพอดี เกม "ขาวเดินก่อน" จึงเป็นภาพหมุน
180 องศาของเกม "ดำเดินก่อน" — ช่อง `i` ↔ `31-i` แล้วสลับสี ตัวเลือกนี้จึงทำ
เป็นการมิเรอร์ตรงรอยต่อกับเอนจิน (`src/game/mirror.ts`) เอนจินยังเล่นเกมเดิม
ทุกอย่าง ส่วนกระดานที่เห็นบนจอเป็นเกมขาวเดินก่อนจริง กติกา คำวิเคราะห์ และ
ชื่อช่องถูกต้องหมด ไม่ใช่แค่เปลี่ยนป้ายชื่อ

`npm run test:logic` ตรวจข้อนี้ไว้: สุ่มตำแหน่งแล้วเทียบว่ารายการตาเดินของ
กระดานที่หมุนแล้ว ตรงกับรายการตาเดินเดิมที่หมุนทีละตา ทุกตำแหน่ง

เกมของ hosbase เปิดแล้วเปลี่ยนฝ่ายที่เดินก่อนกลางคันไม่ได้ ถ้ากำลังเล่นอยู่
**การกดสลับฝ่ายจึงเป็นการเริ่มเกมใหม่ทันที** (ใช้โควตาอีก 2 เกม) — ปล่อยให้กดได้
แต่ไม่มีผลจะงงกว่า กดปุ่มฝ่ายที่เลือกอยู่แล้วซ้ำไม่ทำอะไร ไม่เปลืองโควตา
ถ้ายังไม่ได้เริ่มเกมหรือเกมจบไปแล้ว การกดก็แค่เปลี่ยนค่าไว้ใช้กับเกมถัดไป

## บันทึกเกมและดูย้อนหลัง

ทุกเกมบันทึกเองอัตโนมัติทีละตา (ปิดหน้ากลางเกมก็ยังมีถึงตาล่าสุด) เป็น **ไฟล์ในโฟลเดอร์
`records/` ของโปรเจกต์ เกมละไฟล์** ชื่อไฟล์คือวันเวลาที่เริ่มเกม เช่น
`records/20261016-195512-k3f9.json` กดปุ่ม **บันทึกเกม** บนแถวตั้งค่าเพื่อเปิดรายการ
แล้วกด **ดู** — กระดาน คำวิเคราะห์ ปุ่ม ⏮ ◀ ▶ ⏭ และ "เล่นเอง" ใช้ได้เหมือนตอนเล่นจริง
แต่ **ไม่ต่อ hosbase เลย** ไม่ใช้โควตา ไม่ต้องมีเน็ต

```json
{
  "v": 1,
  "id": "20261016-195512-k3f9",
  "startedAt": 1792155312000,
  "updatedAt": 1792155498000,
  "firstMover": "B",
  "result": "ฝ่ายดำชนะ — ฝ่ายขาวเดินไม่ได้แล้ว",
  "moves": [
    [27,22],
    [4,9],
    [2,11,18]
  ]
}
```

* `moves` คือเส้นทางของแต่ละตา (เลขช่อง 0..31 บนกระดานที่เห็นบนจอ กินหลายต่อมีช่องกลางทาง)
  `result` เป็น `null` ถ้าเกมยังไม่จบตอนบันทึกล่าสุด
* ไม่เก็บคำวิเคราะห์ ตอนเปิดดู `replayPlies()` เล่นไล่ใหม่จากต้นเกม ได้คำวิเคราะห์ครบ
  และตรวจไปด้วยว่าทุกตาถูกกติกา — ไฟล์ที่เสียหรือถูกแก้มือจนผิดกติกาจะเปิดไม่ได้
  (ไฟล์ที่อ่าน JSON ไม่ออกจะไม่ขึ้นในรายการ)
* เบราว์เซอร์เขียนไฟล์เองไม่ได้ จึงให้ dev server ของ vite รับเขียนแทนผ่าน
  `/api/records` (`records-server.ts`) — **ต้องเปิดผ่าน `npm run dev` หรือ
  `npm run preview`** ถ้าเปิดแบบอื่น หน้าต่างบันทึกเกมจะขึ้นแจ้งว่าบันทึกลงไฟล์ไม่ได้
* `records/` อยู่ใน `.gitignore` เพราะเป็นเกมของแต่ละเครื่อง ถ้าอยากเก็บเข้า git
  ให้ลบบรรทัดนั้นออก
* ปุ่ม **ส่งออก / ส่งออกทั้งหมด / นำเข้าไฟล์** ในหน้าต่างบันทึกเกมยังใช้ได้ ไว้ส่งเกมให้คนอื่น
  หรือดึงไฟล์จากที่อื่นเข้ามาในโฟลเดอร์
* บันทึกรุ่นแรกเก็บใน `localStorage` — เปิดหน้าเว็บครั้งแรกหลังอัปเดต จะย้ายขึ้นเป็นไฟล์
  ให้เอง แล้วลบของเดิมเมื่อเขียนครบ
* เปิดดูบันทึกระหว่างมีเกมเล่นอยู่ = หยุดเกมนั้น (บันทึกไว้ว่าหยุดกลางคัน)
  เพราะเกมฝั่ง hosbase ปิดไปแล้วเล่นต่อไม่ได้

## กัน rate limit

hosbase เป็นเซิร์ฟเวอร์ฟรีของคนคนเดียว ถ้าเปิดเกมรัวๆ มันจะปิดการเชื่อมต่อด้วย
policy violation (code 1008) เพดานใน `src/engine/hosbase.ts` ยกมาจากตัว Python:

| ตัวคุม | ค่า | ทำอะไร |
|---|---|---|
| `MIN_GAP` | 5 วิ | เว้นระยะระหว่างการเปิดเกมใหม่ |
| `MAX_PER_HOUR` | 40 เกม | เพดานเกมใหม่ในหนึ่งชั่วโมง (นับแบบเลื่อนหน้าต่าง) |
| `MIN_SEND_GAP` | 400 มิลลิวิ | เว้นระยะระหว่างเฟรมที่ส่งออก ทุกชนิด |

ตัวนับเกมเก็บใน `localStorage` รีโหลดหน้าเว็บก็ไม่รีเซ็ต และการส่งทุกครั้งเข้าคิว
เรียงกันหมด (`serialize()`) เอนจินสองตัวจึงยิงพร้อมกันไม่ได้ โควตาที่เหลือโชว์
อยู่บนหัวหน้าเว็บ

โหมด "เล่นเอง" เดินให้อัตโนมัติ ช้าสุดที่เลือกได้คือทุก 2 วินาที — การเดินในเกม
เดิมไม่ได้เปิดเกมใหม่ จึงไม่กินโควตา แต่ก็ยังไม่ควรรัว

## ทำไมต้องมี proxy

hosbase ตรวจ header `Origin` ต้องเป็น `https://hosbase.com` เท่านั้น ซึ่ง
JavaScript ในเบราว์เซอร์ตั้งเองไม่ได้ (เบราว์เซอร์เป็นคนเติมให้เอง) เลยให้
WebSocket วิ่งไปที่ `/hosbase` บน dev server ของ vite แล้วให้ vite เป็นคน
ต่อออกไปพร้อมเขียน header ให้ถูก — ดู `vite.config.ts`

เพราะแบบนี้ `npm run build` แล้วเปิดไฟล์นิ่งๆ จะใช้ไม่ได้ ต้องมี dev server
หรือ `npm run preview` (ซึ่งใช้ proxy ชุดเดียวกัน) หรือ reverse proxy ของตัวเอง

## คำวิเคราะห์มาจากไหน

hosbase ตอบมาแค่ตาเดินเปล่าๆ ไม่มีเหตุผลแนบมา คำอธิบายทั้งหมดใน
`src/game/analyze.ts` เป็นของเราเอง และ **ไม่มีการให้คะแนนตำแหน่ง** — ไม่เดาว่า
เอนจินคิดอะไร ไม่จัดอันดับว่าตาไหนดีกว่าตาไหน รายงานเฉพาะสิ่งที่อ่านออกจาก
กฎหมากฮอสตรงๆ ซึ่งตรวจสอบย้อนได้ทุกข้อ

* ตานี้เป็นตาบังคับไหม (มีตาเดียวให้เดิน) และเลือกได้ทั้งหมดกี่ตา
* กติกาบังคับกินหรือเปล่า กินอะไรที่ช่องไหน และตานี้มีทางกินได้มากที่สุดกี่ตัว
  (หมากฮอสไทยไม่บังคับให้กินมากที่สุด เลือกทางไหนก็ได้ — ตรงนี้มักน่าสนใจ)
* ขึ้นฮอสหรือยัง
* ก่อนเดิน ตัวไหนกำลังโดนขู่อยู่บ้าง และตานี้ถอยตัวที่โดนขู่ออกมาหรือเปล่า
* หลังเดินแล้ว อีกฝ่าย **ถูกบังคับ** ให้กินอะไรต่อ กี่ทาง มากสุดกี่ตัว
* ถ้าอีกฝ่ายไม่แก้ ตาหน้าเราจะกินอะไรได้
* ถอนหมากออกจากแถวบ้านไหม เหลือกันแถวหลังกี่ตัว และตอนนี้ฮอสฝ่ายละกี่ตัว
* รายการตาอื่นที่เดินได้ในตานั้น ไม่เรียงลำดับความดี แค่บอกว่ามีอะไรให้เลือกบ้าง

## เทสต์

```bash
npm run test:logic    # กฎการเดิน: เล่นสุ่ม 200 เกม ตรวจว่าไม่มีตาผิดกติกา (ออฟไลน์)
npm run test:endgame  # เสียบเอนจินปลอม เล่น 120 เกม ตรวจว่าจบทุกเกม และบันทึก/เปิดย้อนหลังได้ตรง (ออฟไลน์)
npm run dev           # ต้องรันค้างไว้ก่อน
npm run test:match    # ต่อ hosbase จริง ให้เอนจินเล่นกัน 10 ตา (ใช้โควตา 2 เกม)
```

`test:endgame` เล่นทั้งสองโหมด (ดำเดินก่อน/ขาวเดินก่อน) อย่างละครึ่ง และเสียบเอนจินปลอมผ่าน `new Match(factory)` ได้เพราะ `Match` รับ
factory ของเอนจินเข้ามาทาง constructor เทสต์การจบเกมจึงไม่กินโควตา hosbase เลย

`test:match` ตั้งค่าได้ด้วย `PLIES=20 FIRST=W npm run test:match`
